Three kinds:

**TS2416 (49) — `start()` must return `{ api, internal }`.**

`internal` was optional, defaulting to `never`, and that default is what
produced every over-published API in this codebase. It is now required. A test
app that returned a bare API now returns:

    return { api: theApi, internal: {} };

**`internal: {}` is a real answer, not a formality.** It says *this part keeps
nothing*. Most of these test apps genuinely keep nothing — they exist to prove
one kernel behaviour. Where an app does hold state, move it to `internal` rather
than writing `{}` and leaving it public.

**TS18046 (8) — `vx.app` is `unknown`.**

`ViewContext` is now `<TParams, TInternal, TApi>` — input, state, output. A view
reading `vx.app` to find its **own** state is exactly the mistake the reorder
exists to expose. For each of these, decide honestly:

  * is this state the part keeps? → it moves to `internal`, and the view reads
    `vx.internal`
  * is it something the part genuinely publishes? → it stays on `app`, and the
    app declares it

`test/browser/dialog.browser.test.ts` and `models.browser.test.ts` are the two
to think about rather than pattern-match. Say in your closing comment which way
you went on each and why.

**TS2339 (4) and TS2571 (1)** — fallout from the above. They should disappear.
