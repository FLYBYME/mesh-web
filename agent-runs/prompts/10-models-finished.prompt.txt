================================================================================
WHAT IS WRONG, AND IT IS NOT THE MODELS CODE
================================================================================

15 errors remain, all in tests, and 8 of them are one finding:

    test/models.test.ts: error TS2416: Property 'start' in type 'App' is not
    assignable to the same property in base type 'Application<...>'

**`Models<A>` is invariant, and this repository's typing quietly depends on
bivariance.** `src/contribution/contract.ts` says so in its own comment:

> Concrete contributions stay assignable through **method bivariance** —
> `activate` and `start` are methods, not properties. This was verified rather
> than assumed.

That is how `mesh` works today. `Application.start` declares
`Context<TNeeds, TConsumes>` with **no API parameter**, so every real app widens
it by annotating `start(cx: Context<typeof NEEDS, readonly [], typeof someApi>)`
— and method bivariance permits the narrowing. `MeshClient<A>` survives it
because `call` is a **method**. `Models<A>` does not, because `cx.models('part')`
is a **bare call signature**, and `strictFunctionTypes` exempts methods, not call
signatures.

================================================================================
THE FIX — TAKE THE SOUND ONE
================================================================================

Two ways out. **Build the second.**

**(a) Make `models` method-based** — `cx.models.collection('part')` instead of
`cx.models('part')`. Compiles immediately, no framework change. Rejected: it
leans on the same unsound bivariance everything else leans on, so the answer to
*why is this typed* stays *because TypeScript lets methods be unsound*.

**(b) Give `Application` and `Extension` a type parameter for the API**, so
`start` carries `TApi` properly instead of every app hand-widening its own
signature. **Additive, with a default**, so every existing contribution keeps
compiling untouched — verify that, it is the acceptance criterion below.

(b) is worth the extra work because it makes `cx.mesh.call` *genuinely* checked
rather than checked-by-convention, and this repository exists because its owner
nearly rewrote MoleculerJS for type safety. A cast or a knowing unsoundness here
is a bug, not a style nit.

**If (b) turns out to be impossible** — not merely awkward — stop, implement (a),
and make the report an argument for why. Do not silently fall back.
