THE TASK
================================================================================

Roadmap **A7.7**: accessibility lives in the primitives, or it does not exist.

An Application never writes an element. It writes `Stack`, `Text`, `Button`,
`Input` — *"if nobody writes `div`, nobody writes `HTMLElement` either."* So the
library owns every role, label and focus order, and **an Application cannot patch
around a mistake the library makes.** Nineteen primitives get this right once, or
six hundred call sites get it wrong separately and no review finds them.

**Why now, and not as a later audit:** a schema-driven form vocabulary is being
built in mesh-core against these primitives, in parallel with you. Forms are
where accessibility is least optional — a field with no programmatic label is not
a style problem, it is a field that cannot be filled in — and a *generated* form
reproduces whatever the primitives do across every collection on the platform.
Right underneath, and the generated forms inherit it. Wrong, and the generator
faithfully repeats the defect about a hundred and fifty times.

Audit `PRIMITIVES` and give each one what it owes. `Dialog`, `Input`, `TextArea`,
`Button`, `List`/`ListItem` and `DropZone` are where the real decisions are.

Two that are known to matter:

  * **`spaceIsTextInput`** already exists because Space must activate a `Button`
    and type a space in an `Input`. That is the shape of this whole task: the
    primitive knows what it is, the call site does not. Look for what else is
    the same kind of fact.
  * **A label is a relationship, not a string.** `Input` needs a way to *be*
    labelled by another node — a `label` prop that renders text nearby and
    associates nothing is worse than none, because it looks done.

Report plainly which primitives you changed, which were already correct, and
which need an API change you should not make unilaterally. **A primitive that
cannot be made accessible without a new prop is a finding worth reporting before
it is worth fixing** — say so and stop there for that one.

Do not add a dependency. Do not build a linting layer that inspects descriptions
at run time; the point is that the primitive is correct, not that a checker
complains.
